<h1 align="center">OctoASR GPU 使用手册</h1>

<p align="center">
  <b>中文</b> | <a href="OctoASR-GPU-User-Guide.md">English</a>
</p>

---

本手册适用于部署在 Linux NVIDIA GPU 主机上的 OctoASR Docker 服务。服务使用两套 Torch 模型：ASR 模型负责转写与领域术语识别，Mention 模型负责结合会话和成员上下文处理 @提及。它保持与 OctoASR 一致的转写字段、上下文参数、@Mention、模型管理和日志使用方式，同时以 Docker Compose 提供 GPU 部署、健康检查、审计和镜像升级能力。

默认服务地址为 `http://127.0.0.1:18001`。

## 1. 功能与接口概览

| 功能 | 说明 | 入口 |
| --- | --- | --- |
| 音频转写 | 支持 `.wav`、`.mp3`、`.ogg`、`.webm`、`.m4a`、`.flac`，支持中英混合与互联网办公术语。 | `POST /v1/voice/transcribe` |
| 上下文纠错 | 支持已有文本、会话、个人术语和成员上下文。 | 转写表单字段 |
| @Mention | 将昵称或音译名替换为规范名，并按群聊上下文判断是否自动 @。 | `/mentions`、`/v1/mentions` |
| 模型管理 | 查看当前 ASR/Mention 模型，切换模型并回滚。 | `octoasr-gpu model …` |
| 服务运维 | 启动、停止、重启、状态、环境诊断与日志统计。 | `octoasr-gpu …`、Docker Compose |
| 审计与追踪 | 请求 ID、请求/结果/错误记录、可选原始音频留存。 | `/health`、审计目录 |

服务同时提供 OpenAI 兼容的 `POST /v1/audio/transcriptions` 和 `POST /v1/chat/completions`。业务系统若要获得 OctoASR 的完整字段，应使用 `/v1/voice/transcribe`。

## 2. 部署前检查

目标主机需要 Linux、NVIDIA GPU、NVIDIA 驱动、Docker Engine、Docker Compose v2 与 NVIDIA Container Toolkit。默认构建组合为 Linux `x86_64`、CUDA 12.8、PyTorch 2.7.1、cu128 wheel。

```bash
uname -m
docker --version
docker compose version
nvidia-smi
docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

最后一条命令也必须能显示 GPU。若宿主机可见 GPU、容器不可见，请修复 NVIDIA Container Toolkit 后再继续。ARM64 主机必须为 `BASE_IMAGE`、`TORCH_VERSION` 和 `TORCH_INDEX_URL` 选择完整匹配的组合，不能只替换其中一个。

进入 GPU 部署项目并确认部署文件完整：

```bash
PROJECT_DIR=/absolute/path/to/octoasrtorch
cd "$PROJECT_DIR"

for f in Dockerfile compose.yaml .env.example qwen3_asr_openai_server.py qwen3_asr_audit.py; do
  test -f "$f" || { echo "缺少部署文件：$f"; exit 1; }
done
```

## 3. 准备 ASR 与 Mention 模型

ASR 与 Mention 都使用完整的 Torch/Transformers checkpoint。每个模型目录本身都必须包含 `config.json`、权重和所需的处理器/分词器文件；不要将模型复制到 Docker 构建上下文。

```bash
ASR_MODEL_DIR=/srv/models/OctoASR-1.7B-Torch
MENTION_MODEL_DIR=/srv/models/OctoMention-2B-Torch

test -f "$ASR_MODEL_DIR/config.json" && echo 'ASR 模型可用'
test -f "$MENTION_MODEL_DIR/config.json" && echo 'Mention 模型可用'
find "$ASR_MODEL_DIR" -maxdepth 1 -type f | head
find "$MENTION_MODEL_DIR" -maxdepth 1 -type f | head
```

模型通过只读挂载提供给容器：ASR 模型挂载到 `/models/asr`，Mention 模型挂载到 `/models/mention`。模型文件不会进入镜像层，升级或重新创建容器也不会修改模型目录。

## 4. 配置 `.env`

```bash
cp .env.example .env
```

编辑 `.env`，至少配置以下内容：

```dotenv
# 镜像、CUDA 与 GPU
QWEN_ASR_IMAGE=octoasr-gpu:latest
BASE_IMAGE=nvidia/cuda:12.8.0-devel-ubuntu22.04
TORCH_VERSION=2.7.1
TORCH_INDEX_URL=https://download.pytorch.org/whl/cu128
QWEN_ASR_HOST_PORT=18001
QWEN_ASR_GPU=0

# 两个 Torch 模型的宿主机绝对路径
QWEN_ASR_MODEL_DIR=/srv/models/OctoASR-1.7B-Torch
OCTOASR_MENTION_MODEL_DIR=/srv/models/OctoMention-2B-Torch

# 服务功能
OCTOASR_VAD_ENABLED=true
OCTOASR_AUTO_MENTION_ENABLED=true
OCTOASR_AUTH_TOKEN=

# 审计与日志
QWEN_ASR_AUDIT_HOST_DIR=./data/audit
QWEN_ASR_AUDIT_ENABLED=true
QWEN_ASR_AUDIT_SAVE_AUDIO=false
QWEN_ASR_LOG_MAX_SIZE=20m
QWEN_ASR_LOG_MAX_FILE=5
```

| 配置 | 说明 |
| --- | --- |
| `QWEN_ASR_GPU` | 共享机器填写单个 GPU 编号，如 `0`；独占机器可填 `all`。所选物理卡在容器中显示为 `cuda:0`。 |
| `QWEN_ASR_MODEL_DIR` | ASR 模型绝对路径。 |
| `OCTOASR_MENTION_MODEL_DIR` | Mention 模型绝对路径。留空可关闭语义 Mention 判断，但用户词表替换仍可用。 |
| `OCTOASR_VAD_ENABLED` | 是否对长音频启用自动分段。 |
| `OCTOASR_AUTO_MENTION_ENABLED` | 是否默认开启自动 @Mention。单次请求可以覆盖。 |
| `OCTOASR_AUTH_TOKEN` | 非空时启用 Bearer Token 鉴权。不要提交含 token 的 `.env`。 |
| `QWEN_ASR_AUDIT_SAVE_AUDIO` | 是否在审计目录保存原始音频。生产环境按隐私和留存政策设置。 |

创建审计目录并验证配置：

```bash
set -a
. ./.env
set +a
install -d -m 700 "$QWEN_ASR_AUDIT_HOST_DIR"
test -f "$QWEN_ASR_MODEL_DIR/config.json"
test -f "$OCTOASR_MENTION_MODEL_DIR/config.json"
docker compose config
```

渲染配置应包含端口映射、`gpus: all`、ASR 与 Mention 的只读模型挂载，以及审计目录挂载。

## 5. 构建、启动与健康检查

```bash
docker compose build
docker compose up -d
docker compose ps
```

首次启动会依次加载 ASR 与 Mention 模型，健康检查的初始等待时间为 120 秒。查看加载过程：

```bash
docker compose logs --follow qwen3-asr-api
```

服务显示 `healthy` 后检查：

```bash
API_PORT=18001
curl -sS "http://127.0.0.1:${API_PORT}/health" | python3 -m json.tool
```

预期结果包含模型、GPU 和审计状态：

```json
{
  "status": "ok",
  "asr_model_loaded": true,
  "mention_model_loaded": true,
  "gpu": "cuda:0",
  "audit": {"enabled": true, "writable": true}
}
```

也可打开交互式接口文档：`http://127.0.0.1:18001/docs`。生产环境应仅向受控网络暴露该地址。

## 6. 使用命令行

`octoasr-gpu` 是 GPU 版管理命令。它与 Docker 服务共用 `.env` 和模型目录。

```bash
# 服务与诊断
octoasr-gpu start
octoasr-gpu stop
octoasr-gpu restart
octoasr-gpu status
octoasr-gpu doctor
octoasr-gpu port
octoasr-gpu port 19001

# 转写
octoasr-gpu transcribe meeting.wav
octoasr-gpu transcribe meeting.wav --format json --output meeting.json
octoasr-gpu transcribe meeting.wav --hotwords 'FastAPI,Kubernetes,Code Review'

# 模型
octoasr-gpu model list
octoasr-gpu model info
octoasr-gpu model use OctoASR-1.7B-Torch --type asr
octoasr-gpu model use OctoMention-2B-Torch --type mention
octoasr-gpu model rollback

# Mention、日志
octoasr-gpu mentions
octoasr-gpu logs --follow
octoasr-gpu logs --errors
octoasr-gpu logs --stats --hours 24
```

模型切换会预检 checkpoint、等待在途请求结束、加载新模型并运行健康检查；失败时自动保留旧模型。修改 GPU、端口、模型路径或审计配置后，使用以下命令重新创建服务：

```bash
docker compose up -d --force-recreate
```

## 7. 音频转写 API

### `POST /v1/voice/transcribe`

请求类型为 `multipart/form-data`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- |
| `audio` | file | 是 | 支持 `.wav`、`.mp3`、`.ogg`、`.webm`、`.m4a`、`.flac`。默认最大 30 MiB、最长 660 秒。 |
| `context_text` | string | 否 | 已有文本；保留末尾 5000 字符。 |
| `chat_context` | string | 否 | 会话上下文；保留末尾 20000 字符。 |
| `personal_context` | string | 否 | 热词与个人纠错上下文；保留末尾 10000 字符。 |
| `member_context` | string | 否 | 成员上下文；保留末尾 5000 字符。 |
| `mode` | string | 否 | `smart`、`append_only`、`edit_only`，默认 `smart`。`edit_only` 必须提供 `context_text`。 |
| `disable_auto_mention` | boolean | 否 | 当前请求是否关闭自动 @Mention。 |

```bash
TEST_AUDIO=/absolute/path/to/meeting.m4a
REQUEST_ID=meeting-20260929-001

curl -sS -X POST "http://127.0.0.1:${API_PORT}/v1/voice/transcribe" \
  -H "X-Request-ID: ${REQUEST_ID}" \
  -H "Authorization: Bearer ${OCTOASR_AUTH_TOKEN}" \
  -F audio=@"$TEST_AUDIO" \
  -F personal_context=$'## 术语\n- FastAPI\n- Kubernetes\n- Code Review' \
  -F chat_context='讨论 GPU 服务上线和模型切换。' \
  -F member_context='小明=Xiaoming; 老王=Wang Wei' \
  -F mode=smart
```

响应字段与 OctoASR 保持一致：

```json
{
  "status": 200,
  "text": "@Xiaoming 请确认 Kubernetes 集群的 Code Review 结果。",
  "mention": {
    "should_mention": true,
    "targets": [{"display_name": "Xiaoming"}]
  },
  "m": "OctoASR-1.7B-Torch",
  "engine": "torch-cuda",
  "usage": {
    "asr": {"model": "OctoASR-1.7B-Torch", "called": true, "input_tokens": 128, "output_tokens": 24},
    "mention": {"model": "OctoMention-2B-Torch", "called": true, "input_tokens": 78, "output_tokens": 12}
  }
}
```

`smart` 与 `append_only` 会将 `context_text` 和新转写结果自然拼接；`edit_only` 仅返回基于已有文本编辑后的结果。Mention 模型不可用、未配置或请求显式关闭时，`usage.mention` 会说明 `skipped` 原因，转写不会失败。

### `GET /v1/voice/config`

```bash
curl -sS "http://127.0.0.1:${API_PORT}/v1/voice/config" | python3 -m json.tool
```

该接口返回当前最大文件大小、最大时长、引擎、VAD、自动 Mention 和鉴权是否启用等非敏感运行信息。

### OpenAI 兼容转写

已有 OpenAI 客户端可继续使用：

```bash
curl -sS -X POST "http://127.0.0.1:${API_PORT}/v1/audio/transcriptions" \
  -H "Authorization: Bearer ${OCTOASR_AUTH_TOKEN}" \
  -F model=octoasr-gpu \
  -F language=Chinese \
  -F response_format=verbose_json \
  -F file=@"$TEST_AUDIO"
```

需要 `mention`、`usage.asr`、`usage.mention` 等完整字段时，请使用 `/v1/voice/transcribe`。

## 8. @Mention 管理

启动服务后访问 `http://127.0.0.1:18001/mentions`，即可在网页中新增、编辑和删除“昵称 → 规范名”映射。也可通过接口管理：

```bash
curl -sS "http://127.0.0.1:${API_PORT}/v1/mentions"

curl -sS -X POST "http://127.0.0.1:${API_PORT}/v1/mentions" \
  -H 'Content-Type: application/json' \
  -d '{"alias":"小明","name":"Xiaoming"}'
```

用户词表替换优先于语义判断。群聊场景中，Mention 模型会结合 `chat_context` 与 `member_context` 决定是否添加 @；没有足够依据时保留原文。

## 9. 日志、审计与故障定位

Docker 日志默认使用 `json-file` 驱动轮转，单个文件最大 20 MiB，保留 5 个文件。常用命令：

```bash
docker compose logs --tail=200 qwen3-asr-api
docker compose logs --since=30m --timestamps --follow qwen3-asr-api
docker compose ps
docker compose exec qwen3-asr-api nvidia-smi
docker stats qwen3-asr-api
```

服务为每个请求返回 `X-Request-ID`。发生错误时记录该值，再查询日志和审计记录：

```bash
set -a
. ./.env
set +a

find "$QWEN_ASR_AUDIT_HOST_DIR" -type f -printf '%TY-%Tm-%Td %TT %p\n' | sort
python3 -m json.tool "$QWEN_ASR_AUDIT_HOST_DIR/requests/${REQUEST_ID}.json"
python3 -m json.tool "$QWEN_ASR_AUDIT_HOST_DIR/results/${REQUEST_ID}.json"
python3 -m json.tool "$QWEN_ASR_AUDIT_HOST_DIR/errors/${REQUEST_ID}.json"
tail -n 50 "$QWEN_ASR_AUDIT_HOST_DIR/events.jsonl"
```

| 状态码 | 处理方式 |
| --- | --- |
| `400` | 检查音频格式、大小、时长、`mode` 或 `edit_only` 的 `context_text`。 |
| `401` | 检查 `Authorization: Bearer <token>`。 |
| `422` | 检查表单字段和 JSON 请求格式。 |
| `500` | 保留请求 ID，查看 ASR/Mention 运行日志、模型挂载与 GPU 显存。 |
| `503` | 模型正在加载；等待 `/health` 通过后重试。 |

## 10. 升级、回滚与停止

升级前保留当前镜像标签：

```bash
set -a
. ./.env
set +a
docker tag "$QWEN_ASR_IMAGE" octoasr-gpu:rollback-YYYYMMDD
docker compose build
docker compose up -d --force-recreate
```

升级后依次验证 `/health`、普通转写、Mention 和审计写入。若需回滚，在 `.env` 中指定保留标签后重新创建：

```dotenv
QWEN_ASR_IMAGE=octoasr-gpu:rollback-YYYYMMDD
```

```bash
docker compose up -d --force-recreate
```

停止服务但保留模型和审计数据：

```bash
docker compose down
```

不要使用 `docker system prune`、`docker container prune` 或 `docker image prune -a`。这些命令可能影响同一主机上的无关服务；模型和审计目录是宿主机持久化数据，应按数据留存规则单独管理。

## 11. 安全建议

- 服务默认只应绑定或暴露在受信任网络中；对公网部署时使用 TLS、认证、请求大小限制和限流反向代理。
- 审计目录可能包含音频、转写、上下文和成员信息，应使用受限目录权限和明确的保留周期。
- `.env` 中的 token、模型路径、GPU 选择和内部地址不得提交到版本库。
- Chat Completions 的远程音频仅允许公网 HTTPS，且受到超时、大小与重定向限制；生产环境仍应配置出口网络策略。
